# Waggie Tail Positive Instruction Standard

Status: LOCKED
Date: 2026-08-15

## Purpose

All Waggie Tail instructions describe the intended result directly. This standard applies to blueprints, tasks, prompts, tests, code comments, operating procedures, and agent contracts.

## Required Instruction Pattern

Every instruction contains the relevant combination of:

1. Outcome.
2. Required behavior.
3. Required data.
4. Required authority.
5. Acceptance condition.
6. Verification method.
7. Approval point.

## Constraint Pattern

Express constraints through:

- Eligibility.
- Permissions.
- Evidence.
- State transitions.
- Publication gates.
- Approval workflows.
- Audit records.
- Dependency order.

## Approved Examples

### Publishing

> Profile publication requires an active source policy, current status, duplicate clearance, media authorization, field provenance, and an operational removal path.

### Dog Voice

> Medical, behavioral, compatibility, urgency, and adoption claims require exact approved source evidence.

### Status

> A missing source record maps to Status Unknown and starts verification.

### Batch Processing

> Each invalid record is isolated while the remaining batch continues.

### Build Program

> Build the complete Waggie Tail platform through dependency milestones. Each milestone advances the integrated product and opens the next verified dependency.

### Testing

> A passing statement requires a completed test run and captured result.

## Repository Enforcement

Repository reviews include a language scan for prohibition-focused instruction patterns. Each detected instruction is rewritten as an affirmative behavior, gate, permission, evidence requirement, or state transition.

Quoted third-party text and legal source language remain exact when source integrity requires exact wording.
